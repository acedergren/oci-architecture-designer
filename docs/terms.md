# Project usage terms

**Effective date: 2026-10-31.** Approved by the project owner.

## Project and scope

OCI Architecture Designer is a community software project that supplies skills and local helpers for architecture work. It is not an Oracle product or an Oracle-endorsed certification service. Your use of an AI host, Oracle services, connected tools and other applications remains subject to the agreements applicable to those systems.

## Existing rights remain unchanged

No open-source license has been selected for the public repository. These terms do not grant a new software license or additional redistribution rights. Public access to the source is not a statement that every use or redistribution is permitted.

Oracle names, marks, artwork, fonts and toolkit materials retain their existing ownership, notices and restrictions. The Oracle-internal package and supplemental library must remain within their authorized audience. Do not copy their binaries or private metadata into a public package. Obtain the rights needed for the source files, fonts, customer material and outputs used in your task.

## Authorized work and information

Use the plugin only for work and information you are authorized to access and process. You remain responsible for selecting an appropriate AI host and tool configuration, protecting sensitive information and complying with applicable organizational requirements. The [privacy notice](privacy.md) describes the project's processing boundaries; it does not replace your host's or employer's policies.

## Outputs and verification

Architecture recommendations and generated artifacts require review before operational use. A structural validator pass does not establish visual quality, correct font rendering, semantic completeness, application editability, reachability, deployment readiness, compliance or certification.

Review requirements, assumptions, current service information and actual application behavior. Keep missing checks marked NOT_VERIFIED. Confirm generated commands, configuration and infrastructure changes before applying them to an environment.

## Separate external actions

Installing a plugin, publishing a release, sharing an artifact, deploying infrastructure and changing account permissions are separate actions. A diagram or advisory request does not itself authorize those actions. Use the approvals and controls applicable to the task and environment.

## Questions and revisions

Questions can be directed to the maintainer through the [repository](https://github.com/acedergren/oci-architecture-designer), without disclosing confidential information. Approved revisions should state their effective date and remain traceable in repository history. Any later software-license choice or change to Oracle asset permissions requires a separate explicit decision.
